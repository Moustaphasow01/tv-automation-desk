# OOS technical completion without native session candles

Owner: simulation / desk-oos-batch, ADR-0049. Authorized by the operator for 03/07/2026.
No ENGINE, SMC3 parser, frozen plan, PREMARKET or analytical policy changes.

## State and publication

Use the existing terminal state `COMPLETED` and checkpoint `COMPLETED`, with
`run_meta.result_classification=UNSCORABLE_MARKET_GAP`, `scorable=false`, reason
`UNDECLARED_MARKET_SESSION_GAP`. This is **technical coverage**, not an ENGINE result.
No SQL migration is needed. Existing JSONB integration metadata stores the receipt;
post-freeze CAS writes guard the pinned identity columns without rewriting them.

The proof requires scoped consecutive native M15 indices, a last confirmed bar close
before session end, and the next available native bar at/after session end. The worker
does not step into the next session, alter the clock, synthesize bars, or recompute metrics.
`evidence/market-session-exhausted.json` is immutable and SHA-256 pinned in PostgreSQL.
It preserves the plan and manifest hashes, last native close, next native open,
gap start, gap end (the configured session boundary), provenance and reason.

The replay completion receipt and seven performance artifacts remain mandatory for
**scorable** `COMPLETED` days. An unscorable day never writes those artifacts.
`get_run_result` returns a verified technical receipt with `audit=null`, absent
performance values, no result artifact hashes, and `recalculated=false`.
No pending day, PREMARKET bundle, or other pre-freeze read receives this information.

Coverage lists keep the day visible with FROZEN_PLAN and REPLAY_ATTEMPTED true.
Every performance metric and its denominator excludes this classification.
The batch/month projections expose `UNSCORABLE_MARKET_GAP_DAYS` separately.
Terminal requests/retries return the existing classification without another UI command.
After a crash between receipt write and SQL commit, retry verifies and commits the same
receipt without replay, recapture or changing the frozen plan.

## Explicit GAP versus undeclared gap

Read only the GAP records in the exact verified frozen bytes, with the parser's existing
semicolon/pipe representation and V1 Europe/Paris offset. Never add a missing record.
A predeclared covering GAP is not classified as undeclared. Only the installed ENGINE
can apply its GAP semantics and publish a final audit. If no such audit is possible,
`DECLARED_MARKET_GAP_ENGINE_AUDIT_REQUIRED` remains explicit: there is no invented
gap-fill, final clock, result or alternate simulator. V3.9.8's `finalAudit` requires
`time_close >= sessionPlan.entryEnd`; declaring a GAP does not itself supply a candle.

## Future calendar evidence (not retroactive)

Optional `premarket_session_calendar` configuration is indexed by date. Each entry
provides date, symbol, timezone, source, version, known_at, session_open, session_close,
and early_close. Its provenance must predate the PREMARKET cutoff. New manifests can
include this evidence and its SHA-256. The analyst, not the backend, decides whether to
declare GAP before freezing. No plan or scenario is generated by this metadata.

No calendar source is guessed or fetched automatically. The current deployment leaves
this option unconfigured; future cycles require an approved point-in-time source.
Existing manifests are verified and returned unchanged even if later configuration
changes. Capture repair also retains existing calendar metadata rather than dropping it.
